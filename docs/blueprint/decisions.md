# Decisions

## Constraints
- The write guard is not weakened by the notes feature: the coder writes nothing in the task folder and only L1 stores notes (261117-notepads-learnings-handoff)
- Add no new gate and no new popup kind. The Intake Git check popup is also shown when the branch is behind `origin`'s default branch, and a non-gate popup after Intake whose answer is settled is answered by L1 with the recommended choice, so the number of questions per task does not grow — the person decided this at Scope; architecture 4.1 principle 6 (261122-triage-open-feedback)
- Add no new agent and no new run-log line kind (261117-notepads-learnings-handoff)
- SKILL.md stays under 12,500 characters and each rule file L1 reads at once stays under 11,500 characters — tests enforce this (261117-notepads-learnings-handoff)
- Runtime rules carry no temporary exception or workaround wording; the architecture document changes in the same commit so the runtime works as designed (261117-notepads-learnings-handoff)
- The worker turn limit, the "a stopped worker is retried once, then E" handling and the E conditions do not change (261117-notepads-learnings-handoff)
- Judge agents receive only paths and criteria (261117-notepads-learnings-handoff)
- Text in the repository is English. Only the Korean README and the Korean feature overview page are exceptions (261117-notepads-learnings-handoff)
- A release puts the feature and the version-location changes in one commit (261117-notepads-learnings-handoff)
- Steps show as phase digit plus a letter restarting in each phase: ① A Intake, B Explore → Scope; ② A Plan, B Plan Review; ③ A Execute, B Merge; ④ A Verify, B Review → Deliver (`1A`…`4B`); phases keep their numeric ①–④ display and step names are not renamed — the person chose this scheme at Scope (261120-tray-step-letters)
- The state record, the run log, the `/api/tasks` data and the rule files (SKILL.md, phase and profile files, agent definitions, design doc) keep the numeric steps 1–8; letters are worked out only when displaying — they are identifiers (261120-tray-step-letters)
- The letter tables (web `STEP_CODE`, Swift `stepCodes`, architecture template `STEP_CODE`) are explicit literals, not a formula, and are changed together with the name tables (web `STEP_NAME`, Swift `stepNames`); tests compare them — duplicated surfaces must not drift (261120-tray-step-letters)
- G2 (the permission dialog before a risky tool call, such as the commit) and E (the escalation popup) always go to the person, also under delegated approval; a BLOCKER is still fixed before G3 (261120-g3-findings-auto)
- No gate starts the monitor: with the monitor off, the gate reports are read in the chat and the report pointer line gives the task folder — the person chose this with the monitor default (261120-g3-findings-auto)
- The run-log line kinds and their fields stay as they are, so existing task records stay readable by the tally, the monitor and the tray app (261120-g3-findings-auto)
- A monitor settings file with an explicit autostart or report-open value behaves as before (261120-g3-findings-auto)
- The report fields the Phase timeline has (`timeline.end`, `steps[].n/name/start`, `backs[].from/to/at/why`) keep their meaning; only new fields are added, and existing task records show correctly without being rewritten (261122-timeline-back-labels)
- Gate marks (G1a, G1b, G3), the row order and the bar colors of the Phase timeline do not change, and every new monitor UI string has an English and a Korean form (261122-timeline-back-labels)
- No behaviour of the plugin changes in a test cleanup: the blueprint language rule is the only runtime change of 261122-prune-tests-blueprint-en, the capability table file `tools/codex-probe/capabilities.json` stays because the design document cites it, and a test removed as a duplicate names the remaining test that asserts the same thing (261122-prune-tests-blueprint-en)
- The behavior of the git guard is written in the architecture document (4.4, 4.12, and 4.6 for `Cd`) before the code, and the code does nothing outside it; no temporary exception or workaround wording in the runtime rules (261122-harden-g2-deny-rules)
- A crash of `git-guard.py` blocks the call (exit 2), like the other gate hooks (261122-harden-g2-deny-rules)
- A removed or narrowed pattern deny rule (force-push, hook-skipping, `.env.*`) is approved by the person at G1b; no settings file under `~/.claude` is edited by the task, only a diff is handed over (261122-harden-g2-deny-rules)
- `*.key` stays denied by name, and no pattern deny rule is written to match `--force-with-lease` (261122-harden-g2-deny-rules)
- The G1a, G1b and G3 approvals stay popups, G2 and E always go to the person, and every Intake popup (the task-location popup included) is asked every time and never answered by L1 (261122-triage-open-feedback)
- The feedback file in the data folder changes only through the feedback script, and the person sees the closings before they run (261122-triage-open-feedback)
- A size cut of an agent definition never drops a rule: a rule is moved, merged with an identical one or reworded shorter with the same meaning, and a reason is dropped only when the agent's action stays the same; each cut is listed in a record next to the place or code that still states it (261122-reduce-agent-prompt-size)
- Each L2 definition keeps a General, a Research and a Dev section, and the headings, profile headings and verdict lines that tests, scripts and the architecture page generator read stay as they are (261122-reduce-agent-prompt-size)

- Only the architect gets the Edit tool and the scope-guard refusal for unresolvable plan changes applies to the architect's plan file only; other L2 agents, L3 agents and L1 are judged as before, and a Write of the whole plan is judged as before (261122-architect-edit-tool)
- Who changes the plan does not change: a small change before approval is an L1 edit (2 task files or fewer, about 10 lines), anything else goes back to the architect; only L1 writes the approval line and the `Prototype: requested` line, and the `## Revisions` lines stay as they are (261122-architect-edit-tool)
- The architect definition stays at or under 10,981 decoded characters, pinned by `test_architect_edit_rule_and_size` (261122-architect-edit-tool)

## Non-goals
- The four L3 definitions, the skill file and the L1 orchestration files are measured but not edited for size, and the survey's /compact advice is not adopted (261122-reduce-agent-prompt-size)
- The agent installers for Codex and Antigravity (`--install-agents`) are not run by a task; the person is told to run them (261122-reduce-agent-prompt-size)
- The git guard judges nothing outside a my-agent task (there only the hand-merged patterns act), and it does not cover git aliases, scripts that call git, other tools (`gh`, MCP), a plain `$VAR` word in an option, refspec or pathspec slot, or a persistent `git config core.hooksPath` write; the documents state these limits (261122-harden-g2-deny-rules)
- No OS sandbox and no stopping of subprocess reads (`sh -c 'cat x.key'`); the READMEs only state the limit (261122-harden-g2-deny-rules)
- The narrowed force-push patterns can still match a commit message that has ` -f ` after the word `push`; the guard does not deny it and the patterns are not changed further. The `ask` list and the sandbox project's settings copy are not changed (261122-harden-g2-deny-rules)
- The blueprint script has no language check; a blueprint line in another language stays valid until the next update of its entry rewrites it (261122-prune-tests-blueprint-en)
- The review file format and what the reviewer judges are not changed by the gate report work (261120-g3-findings-auto)
- Nothing is pushed, commits or tags, under delegated approval (261120-g3-findings-auto)
- The report-open setting and its default are not changed (261120-g3-findings-auto)
- The tray mini window List shows no step text and no phase display; the Windows tray is not changed — placeholder only, and not part of the request (261120-tray-step-letters)
- The status colors and the 8-cell progress bar are not changed; no letters for gates and no renaming of steps or phases — out of the request (261120-tray-step-letters)
- No notes for researcher and writer work units — only handoff between coder units is covered (261117-notepads-learnings-handoff)
- The coder does not write notes itself during work, and no note survives when a unit stops at the turn limit — this keeps the write guard (261117-notepads-learnings-handoff)
- Notes are not shown in the monitor or the Report tab (261117-notepads-learnings-handoff)
- Notes are not used for the blueprint update or the retrospective (261117-notepads-learnings-handoff)
- The repository does not name other tools or their features (261117-notepads-learnings-handoff)
- The write guard does not judge the contents of a script file that an interpreter runs; only inline code on the command line or in a heredoc is read, and the design document and the guard's description state the limit (261122-triage-open-feedback)
- The guard does not work out the text after an Antigravity `multi_replace_file_content` call from its parts; the call is refused instead (261122-architect-edit-tool)

## Decisions
- scope-guard refuses an architect change to its own plan file when it cannot work out the text after the change (no replacement text reaches the guard, empty text, text not in the file exactly as given, or in the file more than once without `replace_all` being exactly true); the architect changes an existing plan with Edit and writes with Write only the first draft or a full rewrite; the person chose version 0.25.2 at Scope; architecture 4.12 (261122-architect-edit-tool)
- Handoff between work units: L1 stores the notes part of the coder final report in the single file `coder-notes.md` in the task folder and passes its path only to later coder calls. Alternatives not taken: the coder writing the file itself (conflicts with the write guard, and a worktree coder cannot write to the task folder), one notes file per unit — architecture document Q31 (261117-notepads-learnings-handoff)
- Notes are written and read during the task. This differs from the blueprint and the retrospective, which are written after the task ends (261117-notepads-learnings-handoff)
- The notes part is stored up to 10 lines not counting blank lines; beyond that, the first 10 lines and one truncation line are stored. Notes are treated as data, and the plan wins when it conflicts with a note (261117-notepads-learnings-handoff)
- Coder units run through a workflow also have the script return the notes part together with the first line, and L1 stores it by the same rule — applied from plan-review SHOULD-FIX (261117-notepads-learnings-handoff)
- Like the other records in the task folder, the notes file is kept with the task folder and is not deleted during a revision; entries are told apart by the rev number in their label (261117-notepads-learnings-handoff)
- Inside a step circle under a phase heading (web Dashboard and replay step lists, architecture page rail and step cards) the letter shows alone (`A`); standalone text shows the full label (`3A Execute`); a step outside 1–8 shows its raw number — chosen at Plan Review (261120-tray-step-letters)
- Text that arrives already formatted (the log item `step 5 · Execute`, the gate-tally steps cell) is converted on the web page only (`stepTx`, `stepsText`); `events.py`, `report.py`, `ma_gate_report.py` and the gate-tally files stay numeric — chosen at Plan Review (261120-tray-step-letters)
- The feature pages' walkthrough nodes keep the phase digit (two nodes per phase show the same digit); only the phase and step sentence uses the letters — chosen at Plan Review (261120-tray-step-letters)
- Rule-file excerpts and the design-doc flow text on the architecture page stay numeric, so a card can read `Step 3A · 5. Execute` — they are rule and design text (261120-tray-step-letters)
- Every plugin version raise adds a new entry at the start of the architecture document status line, and `test_arch_doc` pins it (now `v0.72`, plugin 0.25.2) — Scope change at Execute (261120-tray-step-letters)
- Under delegated approval L1 answers G3: `Rework: fix all open items` while a SHOULD-FIX or NITPICK item is open, the take choice when none is; the G3 fix loop is capped at 3 rounds, then E — the person chose 3 at Scope; architecture document Q39 (261120-g3-findings-auto)
- An open risk at G3 does not stop L1's take under delegated approval; L1 lists the open risks in the chat — the person chose this at Scope (261120-g3-findings-auto)
- The monitor's `autostart` is off by default: only JSON `true` starts it at task start or resume and at the tray app's start; the monitor skill and Open Monitor always start it; broken JSON or any other value counts as no value — architecture document Q40 (261120-g3-findings-auto)
- The findings table (`Severity | Found | Fixed | Open`) and the popup layout apply to every gate approval (G1a, G1b, G3), not only G3 — the person asked for this during Scope Review (261120-g3-findings-auto)
- The counts of `findings.py` and of the Report tab come from the same functions in `ma_schema` (`review_state`, `judged_counts`), so the two cannot drift — applied from plan-review (261120-g3-findings-auto)
- The Report tab's legend for a G3 answered by L1 is English-only, like the existing wait legend — applied from plan-review NITPICK (261120-g3-findings-auto)
- scope-guard takes a worktree as the coder's own only when its folder is `agent-<agent_id>`; a coder whose `cwd` is another coder's worktree (a moved session) has the main-tree rules, and relative paths still resolve against that `cwd` — the person asked for it after two tasks where the session's folder moved (direct-261120-worktree-scope-guard)
- In the dev profile L1 checks the session's folder (`git rev-parse --show-toplevel`) before every main-tree hand-out and before 6 Merge; on a mismatch the person is asked, also under delegated approval, because L1 cannot move the session — retrospective proposal 3 of 261120-g3-findings-auto (direct-261120-session-folder-check)
- The session is kept out of coder worktrees by a `Cd(...)` deny rule that `cd-guard.py` adds to the task location's `.claude/settings.local.json` at the start of Execute (dev profile), not by keeping L1's turn open or by L1-made worktrees — the person chose the per-project rule over a rule in the user settings (direct-261121-session-cd-guard); Claude Code 2.1.330 may print "Deny rule Cd(...) matches no tool" at startup, which a probe showed is harmless: a typed `/cd` into an `agent-*` folder is refused (261122-harden-g2-deny-rules)
- Antigravity (`agy`) is a third host by the Codex pattern: a name table (`hosts-antigravity.md`) that an Antigravity-only rule file points to, the Antigravity branch of `ma_host.py` and generated files (`build-antigravity.py`); `SKILL.md` and the Claude Code and Codex contracts do not change. It shipped after `agy plugin validate --strict` and unit tests only, so architecture section 4.15 stays `[proposed]` until a task has run end to end in Antigravity — the person asked for the release (direct-261121-antigravity-host)
- A return on the Phase timeline is one orange ↵ icon with no text, drawn on the row of the step run the task left (`backs[].row`), after that row's bar; the target step code and the reason show only on hover and as the accessible name, and the legend has one general line "went back to an earlier step" — the person chose "arrow icon only" at Scope (261122-timeline-back-labels)
- Marks sit in room kept at the chart's right end, measured in pixels (`16 * n + 8`, 14 px marks 16 px apart), so the room does not depend on the window width and the tray Detail view stays inside the chart — chosen at Plan (261122-timeline-back-labels)
- A row's end is the next row's start; the last row ends at the latest G3 ask at or after its start, else at the last run-log line, never before its start; `timeline.chart_end` is the latest row end and `timeline.end` stays the first G3 ask — fixes a negative duration such as "-1213s" (261122-timeline-back-labels)
- The Phase timeline row summary (start → end, total) runs to `timeline.chart_end`, the same span as the chart; a running task's last bar ends at its last run-log line, not at the current time — applied from plan-review SHOULD-FIX (261122-timeline-back-labels)
- The blueprint text is always English, in a new file and in an existing one, in every project the plugin runs in; a line found in another language is rewritten in English when its entry is updated, and a code name or a screen string quoted inside backticks stays as written — rule 4 of `blueprint-format.md`, design section 4.7.5; the person asked for it (261122-prune-tests-blueprint-en)
- The Codex investigation tool `tools/codex-probe/probe.py` keeps only `snapshot` and `check install` (the install check the design document names); `test_every_function_and_constant_is_reachable` and `test_every_fixture_is_named_by_a_test` keep unreachable code and unused fixtures from coming back — the person chose all four cleanup groups at Scope (261122-prune-tests-blueprint-en)
- A test is removed or merged only when another named test asserts the same thing, when it cannot fail, or when it only confirms that wording retired from the runtime files is absent; absence checks that guard a rule in force (author-machine paths, the retired skill-folder variable, home paths, banned profile and fallback wording, the generator mark on hand-kept pages) stay — Scope criterion 3 (261122-prune-tests-blueprint-en)
- Every test file ends with its direct-run call as the last statement, so all test classes run under discovery and when the file is run directly; names of finished tasks or past versions are not kept as if current (261122-prune-tests-blueprint-en)
- The git guard is a new hook, `git-guard.py` (PreToolUse, matcher `Bash`, Antigravity `run_command`, timeout 30, `onFailure: block`), not part of an existing gate hook, because it must judge the owning session's main thread and its subagents, which no existing hook does; it joins `ma_host.GATE_HOOKS` (261122-harden-g2-deny-rules)
- Verdicts: deny for every form the patterns hard-deny plus `+` refspec, `--mirror`, delete forms, `git commit -n` and a hooks-path override; G2 ask for `--force-with-lease` alone, for an unparsed push or commit that shows no form, and for a command substitution in an option, refspec or pathspec slot; the stricter verdict wins. An ask from a subagent call, or in `bypassPermissions`, becomes a deny on every host (fail closed); Codex releases an ask through one `answer gate=G2` line (261122-harden-g2-deny-rules)
- A hooks-path override is covered when it is on the judged command line (`-c`, `--config-env`, `GIT_CONFIG_KEY_<n>`, `GIT_CONFIG_PARAMETERS`); a variable set earlier and a config file pointed to by `GIT_CONFIG_GLOBAL` are limits stated in 4.4 — the person decided at Plan Review that a plain `$VAR` word is not judged (261122-harden-g2-deny-rules)
- The pattern deny list is 37 rules: 14 narrowed force-push rules, 2 git-only hook-skipping rules, 6 named `.env` rules plus `.env.*.local` instead of `.env.*`, 8 added credential rules, `*.key` unchanged — approved at G1b; the live run (`--setting-sources project`, apart from the user settings) exercised the extension rule `*.p12`, not a home-path rule (261122-harden-g2-deny-rules)
- Settled popup rule: after Intake a popup that is not a gate is not asked when its answer follows from the request, the files or an earlier answer of the person in this task; L1 answers with the recommended choice, records it as given by L1 and shows one chat line. Still asked: G1a, G1b, G3, G2, E, every Intake popup, a popup with no recommended choice, and a popup the person answered earlier with another choice or a question back. The rule is one bullet in `SKILL.md` that replaced the scattered "do not ask" sentences, not an addition to them; under delegated approval the existing rules go on unchanged and the answered popup keeps its `ask` and `answer` lines — the person chose it at Scope (261122-triage-open-feedback)
- A popup is answerable from the popup alone: the question names each thing it asks about with what it contains, each option says what it leads to, and the models preset popup describes each preset in one line — the person asked for it at Scope (261122-triage-open-feedback)
- The Intake Git check fetches with a time limit and counts the commits the branch is behind `origin`'s default branch (a never-pushed branch included; detached HEAD and no `origin` are not counted); a count above 0 is a Git check problem listed in its popup, and with no remote, a failed fetch or a timeout the check goes on and says which case it was — the person chose to show the popup for it at Scope (261122-triage-open-feedback)
- G3 popup recommendation: the rework of all open items while a SHOULD-FIX is open and at the first G3; the take choice after a Rework answer when only NITPICK items are open, and with no open item. What L1 answers under delegated approval does not change (rework while any SHOULD-FIX or NITPICK is open, cap of 3 rounds) — the person chose it at Scope (261122-triage-open-feedback)
- The write guard judges a write made through `python`, `python3`, `node`, `ruby` or `perl` inline code (`interpreter_writes`) by its literal path; a visible write with a path that is not a literal is refused as "cannot tell", one refused write refuses the command, and inline code with no visible write passes — the person chose it at Scope (261122-triage-open-feedback)
- A format rule that the plan lint and the G1b approval hook enforce in code (a check tag with one of four values on every criterion, a criterion mark on a command-checked criterion in a dev work unit, no coder file in the task records folder) is not restated in the plan-reviewer definition; plan-reviewer keeps the plan's-copy tag check, the coverage judgment, the General check-command check and the format rules the lint does not read — the person asked for it (261122-reduce-agent-prompt-size)
- The plan-reviewer's exemption for tasks whose criteria carry no tag was dropped because the code has no such exemption; the verifier still judges a criterion with no tag as before (261122-reduce-agent-prompt-size)
- Within the L2 definitions a rule repeated across the common part and the profiles is stated once; a rule shared by two profiles is stated once only when it stays limited to those two, otherwise it stays in both; the measured saving is 960 characters (2.2%) of the six definitions, below the survey's 15-20%, and is reported as measured (261122-reduce-agent-prompt-size)
- A generated file is listed in the plan under the work unit that changes its source (a planner rule, not a change in the changed-files script) — the person chose it at Scope (261122-triage-open-feedback)
- After the blueprint update L1 checks the blueprint for lines the update deleted and shows them in the chat; a coder worktree is removed (forced form, branch deleted) only after its files are compared and found equal, otherwise it is kept and the difference is shown in the "Open risks" row of the G3 report — Scope criterion 6 (261122-triage-open-feedback)
- The closings of the already-fixed, duplicate and obsolete feedback items (69) run right after the G1b approval, highest number first, and stay closed whatever happens to the rest of the task; the closings of applied items run after G3 with their final texts — Scope criterion 15 (261122-triage-open-feedback)
- A review finding location that is a line range or a folder is matched by an "Applied after review" line (a line inside the range, a file under the folder); a front-cut path under a folder needs two segments, so `tests/other.py` does not close `plugins/my-agent/tests/` — Scope criterion 2; the front-cut rule came from a review SHOULD-FIX fixed at G3 (261122-triage-open-feedback)
