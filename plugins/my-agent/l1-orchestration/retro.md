# After G3: remote update · retrospective

L1 reads this file after G3 `Accept` (dev profile: `Commit`), before the retrospective, and in the dev profile before the G3 popup for "Remote update" (SKILL.md "Procedure files").

## Remote update

Dev profile only. A remote take is a G3 answer that commits like `Commit` and then brings the default branch on `origin` up to this commit, so the person does not type the push.

- **Offer (before the G3 popup):** `git symbolic-ref --short refs/remotes/origin/HEAD` prints `origin/<default branch>`; with no `origin` or no such ref, offer no remote take. Its label is `Commit and push` when the current branch (`git branch --show-current`) is that branch, otherwise `Commit and merge into <default branch>`.
  - It is the second choice, after `Commit`; `Commit` stays the recommended take, and under delegated approval L1 never answers with a remote take.
  - With open review items a popup would hold five choices, so the remote take stands in place of plain `Rework`: `Commit` / `<remote take>` / `Rework: fix all open items` / `Abort`. Shortfalls typed in the Other field are the `Rework` answer (`choice=Rework other=1`).
  - The question says what is sent and where (`origin/<default branch>`). When the project's instructions or blueprint say a push to that branch deploys, say that too.
- **Update (after the commit, dev.md "G3 in the dev profile" item 4):** one git command per call.
  1. `git fetch origin <default branch>`, then `git rev-list --count HEAD..origin/<default branch>`.
  2. Count 0: `git push origin HEAD:<default branch>`. It is a fast-forward to the commit Verify and Review judged, also from another branch, where it is the merge. The G2 permission dialog asks; that is intended. On another branch, then run `git fetch origin <default branch>:<default branch>` so the local branch follows; if git refuses, say so in one line.
  3. Count above 0: do not push. The default branch has commits this commit lacks, and merging them now would put unjudged code on it. Say the count, that the commit stays local, and that bringing them in is a follow-up task (or the person's own merge).
  4. Never force a push, and never push to another branch or remote. A denied dialog, a rejected push or a fetch error is reported in one line with its cause; it does not undo the commit.
  5. Record: `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/run-log.py" merge unit=remote files="<short sha> to origin/<default branch>" how="<pushed | not pushed: reason>" by=L1 --data-dir "<data folder>" --task-dir "<task_dir>"`, and say the same in one chat line.

## Retrospective

After Accept (or Commit) and before deleting `.active`, do these in this order. `Status: done` is written first, so if the session drops during the retrospective, `continue` does not redo G3.

1. Run `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/gate-report.py" tally --data-dir "<data folder>" --task-dir "<task_dir>"`. It writes the decision table, metrics, and cost and tokens per stretch to `gate-tally.md`. On exit 1 (no running task), skip the report, say so in one line, and go to item 5. On exit 3 (could not write `gate-tally.md`), state the printed cause in one line and skip the report. Do not undo the Accept or Commit; go to item 5.
2. Hand it to `my-agent:gate-analyst`. Pass: `gate-tally.md`, the result path `gate-report.md`, and the profile written in the prompt (the `Profile:` value from `intake.md`; gate-analyst cannot read `intake.md`). The first line of the result is `DONE` or `PARTIAL <reason>`.
3. If PARTIAL or an error, do not undo the Accept or Commit; state the cause in one line, skip the copy, and go to item 5.
4. Do gates.md "Check before anything leaves" on `gate-report.md` and run `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/gate-report.py" copy --data-dir "<data folder>" --task-dir "<task_dir>"` (the copy goes to `<data folder>/gate-report/`; if the copy folder already has the same name, `-2` is added). In the chat, show only the two paths (`gate-report.md` in the task folder, and the copy) and the 3 lines of `## Summary` in `gate-report.md`. If copy ends with exit 1 (no report) or exit 3 (could not write the copy), do not undo the Accept or Commit; state the cause in one line and go to item 5.
5. If there is no report (item 1 exit 1·3) or it was PARTIAL·an error (item 3), skip filing the `clear` suggestions. Otherwise, file the items in `gate-report.md` `## Suggested improvements` marked `clear` with `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/feedback.py" add L1 <task-id> "<improvement>" --data-dir "<data folder>"` (not shown in the chat). File other improvements from this task with `add L<1-4>` too. Whenever `gate-tally.md` was written, also when the gate report was skipped or PARTIAL: if its `Judge misses` row is above 0, file one L2 item with `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/feedback.py" add L2 <task-id> "<text>" --data-dir "<data folder>"`, whose text names the criterion the person named at G3, or says the criterion was not named.
6. `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/feedback.py" count --data-dir "<data folder>"`. If a `REVIEW: L<n> …` line appears (4 or more open improvements at one level), tell the person in one line.
7. Missing-call check: run `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/gate-report.py" check --data-dir "<data folder>" --task-dir "<task_dir>"`. It compares this session's subagent transcripts with the `id` of `start:` lines in the run-log. File each `missing start:` line as an L4 improvement with `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/feedback.py" add L4 <task-id> "<improvement>" --data-dir "<data folder>"`; for an `agent=unknown` line, name the meta key problem (no `agentType`) in it.
8. Note in the retrospective each `mode not auto:` line from the item 7 output (a `stop:` line whose `mode=` is not auto).
9. Run `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/usage-snapshot.py" --data-dir "<data folder>" --task-dir "<task_dir>"`. It saves the main session's tokens per step to `main-usage.json` in the task folder, because Claude Code deletes transcripts after a while (architecture 4.8.2 "Task records over time"). On exit 3, state the printed cause in one line; do not undo the Accept or Commit.
10. Task worktree only (a task started with `New task in a worktree`; the script prints `nothing to do` anywhere else): last of all, bring the task log back to the main checkout. Do gates.md "Check before anything leaves" on `<absolute task folder>`, then run `python3 "${CLAUDE_PLUGIN_ROOT}/l4-tools-guards/scripts/task-log-copy.py" --location "<task location>" --task "<absolute task folder>"` and show its line. On `Abort` of that popup, do not run the script: the task log stays only in the worktree. It copies the task folder to the same place in the main worktree (`<main>/<task_dir>/<task-id>`) and the worktree's `<task_dir>/.gitignore` when the main checkout has none. It deletes nothing it did not create and never overwrites. On exit 1 state the cause in one line; do not undo the Accept or Commit.
